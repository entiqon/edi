# Versioning Strategy

This project follows Semantic Versioning (SemVer).

Format:

MAJOR.MINOR.PATCH

## Pre‑1.0

Before v1.0.0: - Breaking changes are allowed. - Canonical models may
evolve. - API contracts are not yet stable.

## Post‑1.0

After v1.0.0: - Canonical models are stable. - Breaking changes require
MAJOR version bump. - Minor versions add backward‑compatible features. -
Patch versions fix bugs only.

## Development Tags

Development builds may use:

v0.x.y‑dev.z

These are not considered stable releases.

Canonical stability is the milestone for v1.0.0.
